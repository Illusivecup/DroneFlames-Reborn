# HostSim — хост-авторитетный мультиплеер (v1.2.0)

Дата: 2026-11-15 · Компоненты: `net/net_session.gd`, `net/hs_codec.gd`, `net/net_config.gd`,
`rust/dfarmy/src/dfnet.rs` (DfDelta), `core/sfx.gd`, `world/fx_layer.gd`, `world/vfx.gd`,
`ui/menus.gd`, `dev/mp_hostsim_test.gd`

## Проблема

Lockstep требует, чтобы **каждый** пир прогонял полную симуляцию. Отсюда два нерешаемых
симптома:

1. Слабое устройство (телефон, старый ноут) не успевает в тир → механизм HOLD_SLOW/HOLD_MAX
   замедляет или останавливает матч **для всех** («ЖДЁМ X · МЕДЛЕННОЕ УСТРОЙСТВО»).
2. Любой недетерминизм (краевой случай модов, запись в симуляцию из UI, float-джиттер) даёт
   несовпадение хэша → полный снапшот мира → «СИНХРОНИЗАЦИЯ С ИГРОКОМ...» снова и снова.

RESILIENT 1–6 (docs/NET_RESILIENCE.md) смягчил последствия, но корень — «симуляция везде» —
устранил только HostSim.

## Идея

**Считает всё только хост.** Гость — терминал: отправляет приказы (тот же
путь `NetSession.sim` → `issue` → `_cmd_rq`, тот же белый список `ALLOWED`, та же проверка
владения `_owns`) и применяет состояние мира из потока дельт. Хост-устройство уже быстрое
(Rust-ядро `df_native`/`dfarmy`), а мощность гостя больше не влияет на темп матча.

- **Рассинхронов не бывает по построению**: гость не симулирует, сравнивать нечего. Хэш-механика
  lockstep (HASH_EVERY, `_hash_rq`, `_queue_resync`) в HostSim не выполняется.
- **Гость не тормозит матч**: HOLD-пороги и `_worst_backlog` — только lockstep. Отставший гость
  просто видит мир с задержкой интерполяции; матч идёт темпом хоста.
- **Полная совместимость транспорта**: ENet (LAN), WebRTC, relay-туннель — дельты идут по
  надёжному каналу, как и ходы lockstep.

## Протокол

Все RPC живут на узле `Net` (как и весь lockstep), доставка надёжная.

| RPC | Куда | Что |
|---|---|---|
| `_hs_state(seq, gt, spd, delta)` | хост → всем | дельта состояния (кадр ≤ 48 КиБ) каждые `HS_DELTA_EVERY` тиров |
| `_hs_frame_begin/_hs_frame_part` | хост → всем | большой кадр (> 48 КиБ) поток чанками по 48 КиБ |
| `_hs_key_begin(n, size, parts)` / `_hs_key_part(i, data)` | хост → одному | полный кейфрейм `Save.net_snapshot` чанками `SNAP_CHUNK` |
| `_hs_rq()` | гость → хосту | «мне нужен кейфрейм» (дыра в дельтах, поздний вход, миграция, провал apply) |

**Кейфреймы** отправляются при позднем входе / реконнекте / миграции хоста (существующие
п входы redirected через `_send_snapshot` → очередь `_hs_keys_rq`), по запросу `_hs_rq`
(сторож гостя: без дельт дольше `HS_GAP_T`), и после провала применения дельты. Плановые
кейфреймы выключены (`HS_KEY_TURNS = 0`): дельты покрывают все поля, постоянные ресторы мира
(6–17 с на 1024²) не нужны; константа осталась как страховка.

### Дельта (HSD1, `net/hs_codec.gd`)

Бинарная секционная структура (StreamPeerBuffer, little-endian):

```text
заголовок: 'HSD1' u32 | seq u32 | game_time f64 | speed u8
SEC_DEL: удалённые id по видам (U/D/M/A/S — erase; Y/F/C — null на месте, инвариант id == индекс)
SEC_ENT: изменившиеся сущности: вид, id u32, маска полей u64, значения put_var/get_var
SEC_MAP: data.owners — blob [bm_len][bm][data_len][data], bm_len 0 = весь массив
SEC_OBJ: блок obj_* — 7 параллельных массивов; режимы 0 (chunk-diff всех), 1
         (рост: хвосты новых объектов + chunk-diff префикса — free-id reuse меняет
         произвольные слоты), 2 (полный блок put_var)
SEC_FX:  события эффектов/звуков (см. ниже)
SEC_SYS: изменившиеся поля подсистем (дипломатия, экономика) — deep-strip со ссылками
SEC_END
```

- **Поля сущностей** — кеш «что уже ушло» по (вид, id): сравнение поэлементно
  (значение/instance_id/hash для контейнеров), в дельту — только изменившиеся. Список полей —
  кешированный `get_property_list` (как у `Save._names`), поэтому новые поля игры подхватываются
  сами. Вложения нормализуются как у `Save.enc`: сущность → `{"$e": тег, "i": id}`; ноды и
  Callable → поле пропускается (скип-лист: `fx`, `flag_node`, `visited` + транзиентная
  симуляция: `path`, `pi`, кулдауны, таймеры — гость не симулирует, кейфрейм их обновляет).
- **Первый кадр** не взрывается на «всё со всем»: `HsCodec.host_prime` заполняет кеш хоста
  значениями мира, который гости построили из сида (генерация детерминирована) — дельта несёт
  только реальные отличия.
- **Сущности, которых нет у гостя** (производство, постройка, ракеты), создаются «голыми» по
  скрипту класса и заполняются полями из дельты; несоздаваемый вид → счётчик `made_fail` →
  гость просит кейфрейм.
- **Интерполяция**: между дельтами позиция юнита/дрона/самолёта/корабля (или `t` ракеты)
  лерпится (`from → to` за `HS_INTERP_T`); на госте `pos` — чисто визуальное поле (симуляция
  не идёт), запись безопасна. Следующая дельта продолжает с текущего лерп-значения.
- **FX**: на госте симуляция не спавнит эффекты. Хост записывает события через центральные
  точки (`Sfx._play/_far/_loop` — только изменение состояния, `FxLayer.spawn` — только
  сим-спавны, `Vfx.on_impact`) в буфер и рассылает их в дельте (лимит `HS_FX_MAX`); гость
  реплеит их локально. Сирены/пожары (`Sfx.loop`) едутся как пары on/off.
- **Сторож**: без дельт дольше `HS_GAP_T` → `_hs_rq`; дольше `HS_DEAD_T` → штатный реконнект;
  незавершённый кейфрейм дольше 25 с → реконнект. `real` сторожа — wall-clock (не ×test_speed).

### Хост: цикл

`_host_turns` в HostSim — упрощённый пейсинг: без `_sync_wait`, без HOLD (гость не может
«держать» хост), команды из `_pending` исполняются на старте тира, `turns[n]` заполняется
локально, `_turn` гостям **не** рассылается. `save_match` (NET 35) — по расписанию как раньше.
Колбэки приказов гостей отвечают оптимистично (`null`), листы обновляются из дельт.

## Миграция хоста

Гость-приёмник (сервер прислал `promoted`) уже владеет последним применённым состоянием: он
становится хостом и **продолжает симуляцию от своей копии** (`_host_turn = hs_seq + 1`, кеш
кодека сброшен — первая дельта несёт полный кадр). Мир отматывается назад максимум на интервал
дельт. Остальные переподключаются и получают кейфрейм. Страна погибшего хоста переходит ИИ
(существующее поведение `player_left`).

## Правила режима

- Выбор — в настройках партии («СЕТЕВОЙ ДВИЖОК»: ХОСТ-СИМ / LOCKSTEP), `GameConfig.engine_i`,
  едется в старт-пакете через `CFG_KEYS`, запоминается в настройках (PREFS). По умолчанию
  **ХОСТ-СИМ**.
- Lockstep остаётся полностью рабочим (откат, разбор детерминизма, LAN-турниры).
- Приватность: как и в lockstep, дельты содержат весь мир (туман — локальный рендер).
- Снаряды (shells/rockets/grenades) — переходные объекты жизни <2 с; в дельтах не едутся,
  попадания видны через FX-зеркало.
- **Rust-ядро**: chunk-diff больших массивов считает `DfDelta` (GDExtension `dfarmy`,
  `rust/dfarmy/src/dfnet.rs`); GDScript-фолбэк байт-в-байт идентичен (LSB-first bitmap), формат
  провода не зависит от сборки. Тесты — `rust/dfarmy/tests/delta.rs`.

## Тест

```bash
godot --headless --path . -- --hs-host   # хост hostsim (LAN-транспорт, 8x скорость)
godot --headless --path . -- --hs-guest  # гость: применение дельт, сторожа, интерполяция
cargo test --manifest-path rust/dfarmy/Cargo.toml   # chunk-diff / zigzag / детерминизм
```

Контрольный прогон (Godot 4.7.2 headless, x8, ~2400 тиров, LAN-класс канала):

```
[MP-HS] RESULT lan-host:  go=true hs=true seq=2409 in=0    out=2410 gap_max=0.00 holds=0 apply_ms=0.0
[MP-HS] RESULT lan-guest: go=true hs=true seq=1454 in=1455 out=0    gap_max=2.57 holds=0 apply_ms=1.1
[MP-HS] PASS lan-host
[MP-HS] PASS lan-guest
```

на госте — 0.5–2.5 мс; постройка дельты на хосте — 0.5–7 мс на тир.

## Контроль потока v1.2.1 («гости тонут»)

Первая реальная проверка HostSim показала: хост живёт, а гости получают дельты
медленно или не получают вовсе. Виноват транспорт, а не симуляция:

1. матч через сервер релея едет base64 + JSON (+120 % объёма);
2. `rtc_link` держал токен-ведро **по сообщениям**: 45 сообщений/с, burst 8 —
   мегабайтные чанки кейфреймов копились в очереди минутами;
3. сжатия не было вовсе (~44 КиБ на дельту × 10 Гц ≈ 4.8 Мбит/с на гостя);
4. контроль потока отсутствовал: очередь хоста и сервера росла без предела,
   «немой» сервер не разрывал утопленного гостя.

Решения v1.2.1:

| Механизм | Что делает |
|---|---|
| **HSC1 (zstd)** | каждая дельта/кейфрейм жмётся до отправки; чанкование — после сжатия; несжимаемое — как есть. На матче x40 к объёму |
| **байтовое ведро** | матч-трафик через релей: 4 МиБ/с, burst 1 МиБ (вместо 45 msg/s); лобби — как раньше |
| **skip по backlog** | `rtc.match_backlog()` > 256 КиБ → хост не строит дельту (кеши кодека обновляются только при отправке — пропуски сливаются в следующий кадр) |
| **skip по отставанию** | гость шлёт `_hs_ack` (applied seq) каждые 2 с; нетто-отставание (разрыв минус прогресс гостя) > 30 ходов → пауза потока |
| **keepalive** | даже в skip-режиме кадр уходит каждые 40 ходов (4 с) — гостевой сторож 6 с не срабатывает |
| **кейфрейм-гейт** | кейфрейм не льётся в трубу с backlog > 512 КиБ; просители остаются в очереди |
| **сервер** | переполнение очереди → сброс старейших пакетов (RelayEvent `out_queue_overflow`) вместо вечного молчания; `--throttle=KiB/s` для стендов |

Новые константы: `HS_SKIP_BACKLOG_B` (262144), `HS_KEY_BACKLOG_B` (524288),
`HS_KEEPALIVE_TURNS` (40), `HS_LAG_SKIP` (30), `HS_LAG_RESUME` (10), `HS_ACK_S` (2.0).
Диагностика: `hs_wire_out/in` (байты провода), `hs_skip_out` (пропущенные построения),
отставание и backlog — в логах `[Net] HS delta ...` и `[MP-HSR] ...`.

## v1.2.2 — режим движка и моды живут через реконнект

- `leave()` сбрасывал `hs_mode` навсегда: гость после реконнекта сидел на
  lockstep-пути (дельты игнорировались, мир замирал), хост после
  «ПРОДОЛЖИТЬ ПАРТИЮ» навсегда уходил в lockstep-pacing. Теперь режим
  восстанавливается в `_rejoin_ok` / `resume_host` из `GameConfig.engine_i`.
- Геймплей-моды включаются на бой в ХОСТ-СИМ (`_suspend_multiplayer_mods(false)`
  в `_start` / `_rejoin_ok` / `resume_host`): симулирует только хост, набор модов
  сверен отпечатком при входе. В lockstep моды по-прежнему выгружаются.
- OBJ-дельта регистрирует новые id объектов в чанках рендера
  (`HsCodec.guest_seeded` + `HsCodec._obj_register`) — постройка гостя появляется
  в тот же кадр, а не после ближайшего кейфрейма.
- Команды вне `ALLOWED` в ХОСТ-СИМ проходят через fallback `_hs_fallback_ok`
  (только не-gw-объекты, без приватных и движковых методов; всё логируется) и
  логируются при отказе — тап гостя больше не умирает молча.
